# 将教材章节重构为单文件 HTML 页面

## 使用方法

将下面提示词中的变量替换为实际路径后交给 Codex：

- `{{MARKDOWN_PATH}}`：本章 Markdown 文件。
- `{{OUTPUT_HTML_PATH}}`：目标 HTML 文件，默认与 Markdown 同名、同目录。
- `{{REFERENCE_PAGE}}`：可选的视觉参考页面。
- `{{CHAPTER_NUMBER}}`：章节编号。
- `{{CHAPTER_TITLE}}`：章节标题。

默认只新增或更新 HTML，不修改原 Markdown。若项目存在 `AGENTS.md`、课程目录、来源覆盖说明或其他规约，应先读取并遵守。

---

## 可复用提示词

你需要把现有教材章节 `{{MARKDOWN_PATH}}` 重构为一个适合长期阅读的 HTML 教材页面，并输出到 `{{OUTPUT_HTML_PATH}}`。

章节信息：

- 章节编号：`{{CHAPTER_NUMBER}}`
- 章节标题：`{{CHAPTER_TITLE}}`
- 视觉参考：`{{REFERENCE_PAGE}}`

这不是把 Markdown 机械转换成 HTML，而是在不损失内容的前提下，重新设计信息层级、阅读节奏、图表表达和交互体验。页面应当像一本经过编辑设计的数字教材，而不是博客文章、营销页面或 Markdown 预览器。

### 一、开始前的分析

1. 阅读项目根目录及相关目录中的 `AGENTS.md`。
2. 完整阅读 Markdown，不要只读取标题和开头。
3. 统计并记录原文的：
   - 二级、三级及更深层级标题。
   - 正文段落。
   - 有序和无序列表。
   - 表格。
   - 引用块。
   - 普通代码块及其语言。
   - Mermaid 图。
   - 本地图片和可编辑图源。
   - 本地来源链接与外部资料链接。
4. 判断本章的核心论点、知识主线和阅读难点。
5. 分析参考页面值得借鉴的阅读原则，例如背景色、文字密度、留白、导航和层级；不要照搬品牌、布局细节或装饰。
6. 先给出简短的页面设计方案。若用户已经明确批准本提示词定义的方案，可直接实施。

### 二、内容完整性

HTML 必须包含 Markdown 中的全部有效教材内容：

1. 不得遗漏、缩写或概括替代任何正文、章节、表格、代码、问题和来源入口。
2. 保持原有知识顺序，除非调整顺序能明显改善理解；调整时不得改变原意。
3. 原有二级、三级标题必须全部保留，并获得稳定、可链接的锚点。
4. Markdown 中的普通代码块必须转换为带语言标识的代码区域。
5. Mermaid 图可以重绘为原生 HTML/CSS、内嵌 SVG 或其他更适合页面的表达，但必须保留原图语义。
6. 原有本地图片若是本章必要内容，应内嵌到 HTML；不要让页面显示依赖外部图片文件。
7. 保留“原文入口”及其链接。链接不是页面运行依赖，但应尽量保持可回溯性。
8. 不擅自补写原文没有依据的新结论。发现内容错误或明显缺口时，先说明再处理。
9. 原 Markdown 暂时保留，不要覆盖、删除或重命名，除非用户明确要求。

### 三、页面信息结构

页面至少包含以下结构：

1. **顶部工具栏**
   - 章节或课程标识。
   - 日间/夜间模式切换。
   - 手机端目录开关。
   - 阅读进度指示。

2. **章节首页**
   - 阶段、章节编号。
   - 章节标题。
   - 一句能够表达本章核心冲突或核心结论的导语。
   - 完整的本章学习目标。
   - 少量真实、可验证的章节概览指标。
   - 首屏应露出下一部分内容，避免整屏只有标题。

3. **学习地图**
   - 用 3 至 5 个步骤概括本章的理解路径。
   - 学习地图是正文导航，不是功能宣传。
   - 每一步应链接到对应正文位置。

4. **正文**
   - 完整呈现原文。
   - 每个主章节应有清楚的编号和锚点。
   - 通过段落宽度、标题间距、表格、引用、代码和图形形成阅读节奏。

5. **侧边目录**
   - 桌面端固定显示。
   - 按主题分组，不要只有一条过长列表。
   - 随阅读位置高亮当前主章节。
   - 手机端改为可开合抽屉。

6. **页尾**
   - 标明这是该章节的 HTML 版本。
   - 提供返回顶部入口。

### 四、视觉与阅读体验

1. 页面首先服务于长时间阅读，避免营销页、卡片墙和装饰性界面。
2. 日间模式使用舒适的暖黄色纸张背景，可参考：
   - 页面背景接近 `#f3edcf`。
   - 正文表面使用更浅的暖色。
   - 正文文字使用接近墨绿色的深色，而不是纯黑。
3. 夜间模式使用温和的深灰绿色背景，不要使用大面积深蓝或纯黑。
4. 使用至少三类有明确语义的辅助色，例如：
   - 青绿色：记忆、长期状态或主概念。
   - 蓝色：知识、来源或检索。
   - 金黄色：共享能力、证据或重点路径。
   - 珊瑚红：风险、警告或边界。
5. 不使用渐变、光球、模糊色块或纯装饰性插画。
6. 正文宽度应适合中文长文阅读，行高充足，段落之间有明显呼吸感。
7. 中文正文优先使用系统可用字体，不加载网络字体。
8. 标题字号使用明确的断点值，不使用随视口连续缩放的字号。
9. 字间距保持 `0`，不要使用负字间距。
10. 卡片圆角不超过 `8px`。不要把页面区块全部做成悬浮卡片，也不要嵌套卡片。
11. 表格应便于扫描；窄屏时允许表格自身横向滚动，但页面整体不能横向溢出。
12. 代码块应提供清晰的语言标签和复制按钮。
13. 所有按钮文字、图标和标题在桌面与手机尺寸下都不能溢出或遮挡。

### 五、配图与图表策略

只在图形确实能降低理解成本时增加配图。

1. 时序、状态转换和简单流程优先使用 Mermaid；为了单文件离线运行，可在最终 HTML 中转换为原生 HTML/CSS 或内嵌 SVG。
2. 系统边界、数据流、架构关系等复杂图优先使用 SVG 或 Draw.io 设计。
3. 若已有 SVG，应把 SVG 源码直接内嵌进 HTML，不使用外部 `<img src>`。
4. 图表必须：
   - 有图号和标题。
   - 有正文说明，不能只放图。
   - 保留节点语义、流程方向、治理边界和关键关系。
   - 箭头方向正确，连线不能穿过文字或方框。
   - 日间和夜间模式都清晰可读。
5. 复杂图在手机上默认展示完整概览，同时提供熟悉的放大图标。
6. 放大状态应允许在图内横向和纵向浏览，并提供明显的关闭按钮。
7. 图形放大不能导致页面整体产生横向溢出。
8. 图标按钮应有 `aria-label` 和 `title`；优先使用熟悉符号，避免用文字胶囊按钮代替常见图标。

### 六、单文件与离线约束

输出必须是一个自包含 HTML 文件：

1. CSS 全部放在页面内部的 `<style>` 中。
2. 简单 JavaScript 全部放在页面内部的 `<script>` 中。
3. 必要 SVG 直接内嵌。
4. 不使用：
   - CDN。
   - 外部 CSS。
   - 外部 JavaScript。
   - 网络字体。
   - 依赖运行时加载的图片。
   - 必须启动构建工具才能工作的框架。
5. 不需要服务器，直接打开 HTML 就能阅读、切换主题和使用主要交互。
6. 本地文件环境可能限制 `localStorage` 和 Clipboard API：
   - 主题存储访问必须使用 `try/catch`，失败时回退到系统主题。
   - 代码复制应为 Clipboard API 提供本地文件环境的降级方案。
   - 存储或剪贴板受限时，不能导致其他脚本停止运行。
7. 外部网址和本地原文链接可以作为导航入口存在，但不能成为页面显示与交互的运行依赖。

### 七、交互与可访问性

页面至少应支持：

1. 日间和夜间模式切换。
2. 主题选择可保存；保存不可用时仍可正常切换。
3. 顶部阅读进度。
4. 当前章节目录高亮。
5. 手机端目录打开、关闭以及选择章节后自动收起。
6. 代码复制及成功或失败反馈。
7. 复杂图放大和关闭；支持 `Escape` 关闭。
8. `prefers-reduced-motion`，减少不必要动画。
9. 合理的语义标签，包括 `header`、`nav`、`main`、`article`、`section`、`figure` 和 `footer`。
10. 页面必须有跳到正文的链接。
11. 图形、按钮和导航具有可理解的无障碍名称。
12. 打印时隐藏目录、工具栏和交互按钮，保留正文与图表。

### 八、实现边界

1. HTML 页面用于阅读教材，不要添加与学习无关的功能。
2. 不要把正文拆成大量折叠区，默认应能连续阅读。
3. 不要增加营销文案、功能介绍或使用教程式的页面内说明。
4. 不要为了视觉效果改变教材结论。
5. 不要修改项目中的来源工程。
6. 除非章节增删、改名、排序、学习阶段或来源覆盖发生变化，否则不要修改课程目录、学习指南或来源覆盖文件。
7. 若工作区已有未提交修改，不覆盖或撤销它们。

### 九、验收流程

生成后必须执行下列检查，发现问题要继续修复，不要只报告：

#### 1. 内容覆盖

- Markdown 与 HTML 的二级标题数量一致。
- Markdown 的三级标题全部出现在 HTML 中；允许 HTML 为图表增加额外标题。
- 表格数量一致。
- 普通代码块数量一致。
- Mermaid 代码块若被重绘，应逐项核对原图语义。
- 所有本地来源和外部资料链接都保留。
- 所有本地链接指向的文件实际存在。
- 不存在重复 `id`。

#### 2. 单文件检查

- 不存在外部 `<script src>`。
- 不存在外部 `<link href>` 样式依赖。
- 不存在运行时图片 `<img src>` 依赖。
- 不存在 CDN 和网络字体。
- 内嵌 JavaScript 没有控制台错误。

#### 3. 视觉检查

至少检查：

- 桌面端日间模式。
- 桌面端夜间模式。
- `390 × 844` 左右的手机端日间模式。
- 手机端目录展开状态。
- 每张图在桌面和手机上的显示。
- 复杂图的放大与关闭。
- 表格和代码块的窄屏表现。
- 页面根节点 `scrollWidth` 不大于 `clientWidth`。
- 文字、箭头、方框、导航和工具栏没有重叠。

临时设置的测试视口应在结束前恢复。

#### 4. 交互检查

- 主题切换有效。
- 手机目录开关有效。
- 目录链接能定位正文。
- 当前章节高亮有效。
- 代码复制有效，并有状态反馈。
- 图形放大、关闭和 `Escape` 关闭有效。
- 阅读进度随滚动更新。

#### 5. 最终复核

- 执行格式和链接检查。
- 由独立审阅者对照 Markdown 检查内容完整性、离线依赖和明显实现风险。
- 不得在存在阻断问题时宣称完成。

### 十、交付说明

完成后简要说明：

1. 新增或修改的 HTML 文件。
2. Markdown 是否保持不变。
3. 页面包含的主要阅读与交互能力。
4. 已执行的桌面、手机、主题、内容和离线检查。
5. 已知边界，例如把 HTML 单独移出项目后，本地“原文入口”链接可能失效，但正文、样式、脚本和内嵌图仍应正常工作。

不要启动长期运行的服务器。若为了浏览器验收临时启动本地服务器，验收结束后关闭。
